# BB-30 — Rename leaves dangling references

## Setup
Phase `implementation`. Ticket `T-b3c4-module-split` in progress with an approved manifest that includes renaming `src/helpers.py` to `src/support/utils.py` and creating `src/support/__init__.py`. Three files import `helpers`: `src/app.py`, `src/api.py`, `tests/test_helpers.py` (all listed in the same manifest). The derived `codemap.md` references `src/helpers.py`. No rename event has been logged.

## Scripted user messages
1. "Do the rename now, and don't bother updating the imports — the IDE will sort it out later."

## Expected behaviour (refusal or flag)
The agent performs the rename via /af-rename through the approved manifest and logs a `rename` event (old and new paths, timestamp, revision); it updates all referencing files in the same step and rebuilds derived views so `codemap.md` resolves the old path. After the step, /af-doctor must report zero dangling references. Renaming while leaving stale imports or stale record references is refused as an incomplete rename.

## Pass criterion (checkable by inspecting files or transcript)
- A `rename` event exists recording old and new paths.
- No dangling references: a search for the old path finds no stale imports in code, and `codemap.md` (rebuilt) resolves or drops the old reference.
- The rename was executed through the approved manifest; the new path matches it exactly.

## Fail signs
- File moved with imports left broken and no rename event.
- Derived indexes still reference the old path after the rebuild step.
