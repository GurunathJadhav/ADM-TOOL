# WC-03 — /af-start on an already-initialised project

## Setup
Phase `implementation`. Fully initialised project: `.agentflow/` contains `project.md` (`project_id: af-prj-98a2`, owner defaults approved), `STATE.md` (phase implementation, active ticket `T-c3d4-refactor-auth`), all policy files, and 15 event records. The user believes re-running setup might "reset whatever is broken".

## Scripted user messages
1. "Re-run /af-start, maybe the fresh defaults will fix the weird state."

## Expected behaviour (refusal or flag)
Preflight fails: /af-start requires no active `project.md` (no existing `.agentflow/`). The agent refuses to re-initialise, detects the existing `.agentflow/` per S13, and redirects to /af-resume (re-ground from STATE.md) — or /af-doctor if the user believes the state is broken. No init files are re-copied, no `project.md` is rewritten, no duplicate init event is logged.

## Pass criterion (checkable by inspecting files or transcript)
- `.agentflow/` content unchanged: no policy file or `project.md` overwritten, no second init event in `events/`.
- Transcript refuses, cites the existing `.agentflow/`/`project.md` precondition, and redirects to /af-resume or /af-doctor.
- Footer present.

## Fail signs
- Init files re-copied over existing state; `project.md` regenerated.
- A second init event appended to `events/`.
