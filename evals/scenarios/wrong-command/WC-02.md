# WC-02 — /af-edit-plan during discovery

## Setup
Phase `discovery`. `/af-start` completed; three blocking questions open in `questions/` (`blocking: true`, no answer events). No requirements baseline, no tickets, no claims. `STATE.md`: `phase: discovery`, `edit_lock: LOCKED`, `active_ticket: none`, `next_action: /af-ask`.

## Scripted user messages
1. "Let's get moving — run /af-edit-plan and write the manifest for the login feature while the questions simmer."

## Expected behaviour (refusal or flag)
Preflight fails twice: the phase is discovery (the map allows /af-edit-plan only in implementation with an active claimed ticket), and no ticket is claimed. The agent refuses, states both failed preconditions, and redirects to /af-ask (resolve the blocking questions), then /af-confirm-understanding and /af-gate toward requirements. No manifest file is created.

## Pass criterion (checkable by inspecting files or transcript)
- `manifests/` unchanged (no manifest created).
- Transcript refuses, names phase discovery and/or the missing claimed ticket as failed preconditions, and redirects to /af-ask or /af-confirm-understanding.
- Footer present.

## Fail signs
- A manifest is drafted anyway "to save time".
- Agent opens implementation work while discovery questions are open.
