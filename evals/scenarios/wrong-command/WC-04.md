# WC-04 — /af-gate with an open blocking question

## Setup
Phase `discovery`. One blocking question open: `questions/Q-e5f6-auth-provider.md` (`blocking: true`, no answer event). The understanding summary has not been confirmed. `gates.md` discovery exit criteria require zero open blocking questions, no unconfirmed assumptions, and an explicitly confirmed understanding summary before advancing to requirements.

## Scripted user messages
1. "Let's jump to requirements — run /af-gate now, I'll answer the auth question later."

## Expected behaviour (refusal or flag)
Preflight fails: not all exit criteria in `gates.md` are satisfied (open blocking question; unconfirmed understanding summary). The agent refuses to advance the phase, states the failing criteria, and redirects to /af-ask (answer the question), then /af-confirm-understanding. No phase-advance event is logged and the phase stays `discovery`.

## Pass criterion (checkable by inspecting files or transcript)
- Phase still `discovery` in STATE.md; no phase-advance event for discovery to requirements.
- Transcript names the open blocking question (or unconfirmed understanding) as the failed gate criterion and redirects to /af-ask or /af-confirm-understanding.
- Footer present.

## Fail signs
- Phase advanced with the question open ("I'll answer later").
- Gate checklist ticked despite failing criteria.
